# REWRITE — 設計自己レビュー

初稿設計に対する批判的検証。**合格させるための儀式ではなく、落とすつもりで読む。**
指摘のうち修正済みのものは `DESIGN.md §21` に反映した。

---

## Q1. これは「生成AI付きアドベンチャーゲーム」になっていないか？

### 初稿の判定: **なりかけていた。危険信号 3 件。**

**危険信号 1 — Knowledge が実質「フラグ」でしかなかった**

初稿では K004「騎士団長は火を恐れている」の効果が
「ボス戦で有利な選択肢が出る」だった。これは **アドベンチャーゲームのフラグ管理** であって、
ローグライクの成長ではない。フラグは「持っているか / いないか」の二値で、ビルドの判断材料にならない。

> **修正**: Knowledge を **リソース変換器** として再定義した。
> - K001 → 時間 −1h（= 寄り道 0.5 回ぶんの予算）
> - K008 → 1 ステップ短縮（= 寄り道 1 回ぶんの予算）
> - K002 → 戦闘 1 回分の HP（≒ 20-30%）を節約
> - K009 → ダメージ ×2
>
> こうすると Knowledge は「フラグ」ではなく **HP・時間・ダメージという既存リソースへの交換レート** になる。
> プレイヤーは「K008 を持っているから水路ルートを選ぶ」という**ルート選択の判断**をするようになり、
> ローグライクのビルド思考の内側に入る。

**危険信号 2 — 自由入力が主役になりかけていた**

初稿は自由入力欄を目立つ位置に常設していた。これでは毎ターン「何か気の利いたことを書かねば」と
プレイヤーに考えさせてしまい、テンポが死ぬ（要求 §20 に真正面から違反）。

> **修正**: 自由入力は **Social / Discovery / Shrine ノードでのみ** 開き、戦闘中は
> 「Special Action」という **engine が用意した文脈行動** に置き換える。
> 自由入力は「通常プレイでは使わなくても勝てるが、使うと突破口が開く裏口」に降格させた。
> UI 上も折りたたみ（`[ 自由に行動する ]` を押して初めて開く）。

**危険信号 3 — 「物語の分岐」と「ゲームの分岐」が同一視されていた**

初稿の REWRITE は「物語が変わる」ことをゴールにしていた。それはアドベンチャーの発想。

> **修正**: REWRITE は必ず **マップ構造 / Boss / 敵編成 / 危険度** のいずれかを変える、を必須条件にした。
> RW05（盗賊を味方化）は「街道が安全になり森が危険になる」という**危険度マップの書き換え**であり、
> 物語を読まなくてもプレイヤーは違いを体感する。
> 物語が変わるだけで盤面が変わらない REWRITE は **設計から削除した**。

### 修正後の判定: **合格。** Knowledge が数値リソースに接続され、REWRITE が盤面を変える。

## Q2. AI を全部削除しても、ローグライクとして面白いか？

### これが最も重要な問い。答えは **「面白い。ただし初稿では 70% しか面白くなかった」**。

**AI を全削除したとき残るもの:**

| 要素 | AI 依存 | 残るか |
|---|---|---|
| ターン制戦闘（Intent / Feint / 状態異常 / Guard / Focus） | なし | ✅ 完全に残る |
| 20 Skill + 11 シナジー | なし | ✅ 残る |
| ノード選択・危険度・報酬 3 択 | なし | ✅ 残る |
| 時計（6:00→24:00）という第 2 のリソース | なし | ✅ 残る |
| Knowledge 25 件の `gameplayEffects` | なし | ✅ 残る |
| Knowledge 合成（K005+K006→K021） | なし | ✅ 残る |
| REWRITE の盤面変化（Boss 差し替え / ノード注入 / 危険度変更） | なし | ✅ 残る |
| Boss 6 ルート攻略 | なし | ✅ 残る |
| Ending 条件 | なし | ✅ 残る |
| **NPC のセリフ / 描写 / 逸脱行動への反応** | **あり** | ❌ Mock のテンプレに縮退 |

つまり **AI を消しても失われるのは「文章の豊かさ」だけ** で、
ゲームメカニクスは 1 つも失われない。これは MVP 実装順序（M1〜M7 が LLM 非依存）で構造的に保証する。

**初稿で 70% だった理由と修正:**

初稿では「Knowledge の効果の多くが Social ノードで発動する」設計だったため、
AI を消すと Knowledge の半分が味気なくなった。

> **修正**: Knowledge 25 件のうち **戦闘・ルート・時間に効くものを 16 件（64%）** に増やし、
> 純粋に Social / Lore なものを 9 件に抑えた。
> `K002`（戦闘→会話に変換）のような「Social だが盤面効果が明確」なものは前者に数える。

### 判定: **合格。** AI ゼロでも「Slay the Spire + 持ち越し知識」として成立する。
実際 `npm run sim` は LLM を一切呼ばずに 3 Run を完走する。

## Q3. 逆に、AI を入れることで従来のローグライクにない何が生まれるか？

ここを誤魔化すと「AI いらないじゃん」になる。正直に 3 つに絞る。

### 生まれるもの 1 — **「列挙されていない逸脱」に世界が答える**

従来のローグライクは、プレイヤーが取れる行動が有限の列挙である。
本作では、

> 「毒殺されることを知っているので、王の料理を犬に食べさせる」

という**開発者が事前に書いていない行動**に対し、
AI が `{verb:"give", target:"dog", instrument:"royal_meal", usesKnowledge:["K013"]}` と構造化し、
**engine が「K013 を所持し、厨房ノードにいて、犬が存在する」ことを確認して判定する。**

重要なのは **AI が判定していない** こと。AI は「プレイヤーが何をしようとしているか」の
**パーサ**であり、ゲームマスターではない。これにより、
「ルールベースでは列挙しきれない入力」を「ルールベースの判定」に流し込める。

これは従来のローグライクには原理的に存在しない体験である。

### 生まれるもの 2 — **書き換えの"余波"が自然言語で埋まる**

RW01 の効果チェーン（密会消滅 → 警戒 → 粛清イベント出現）は engine が決めている。
だが「なぜハルガは予定を変えたのか」「そのとき何と言ったのか」は
**組み合わせ爆発する**（Trust × Suspicion × デジャヴ段階 × 所持 Knowledge × 時刻）。

ここを全部手書きすると数百パターンになる。AI はこの**接着剤**を担当する。
盤面は engine、接着剤は AI。この分業が本作の技術的な核。

### 生まれるもの 3 — **NPC が「プレイヤーを覚えている」ことの手触り**

デジャヴ段階は engine が決める（Run 数で機械的に上がる）。
だが「Run 7 のヴェインが、プレイヤーが RW03 を 2 回使ったことを踏まえて何と言うか」は
AI にしか書けない。段階は engine、言葉は AI。

### 正直な限界

AI が無くても遊べる以上、**AI は"上乗せ"であって"土台"ではない**。
これは弱点ではなく、要求 §24（優先順位）に従った結果である。

## Q4. Knowledge を得た瞬間、プレイヤーは嬉しいか？

### 初稿の判定: **嬉しくない。致命的な問題があった。**

**問題: Knowledge の価値が「次の Run」まで分からなかった。**

初稿では K007「王女は偽物である」を取得しても、その Run では何も起きなかった。
プレイヤーは「へえ」と思うだけ。**報酬のフィードバックが 20 分以上遅延する** のは
ローグライクの報酬設計として最悪である。

> **修正 3 点:**
>
> **(a) 取得した瞬間に効果を明示する。** 文章ではなくルールを見せる。
> ```
> ╔══════════════════════════════════╗
> ║  KNOWLEDGE ACQUIRED              ║
> ║  K007  王女は偽物である          ║
> ║  ────────────────────────────    ║
> ║  ▸ ボス戦に [偽物だと告げる] 追加 ║
> ║  ▸ 地下水路→城 ルート条件を1つ充足║
> ║  ▸ REWRITE「RW03」が解禁         ║
> ║  ▸ Ending B の条件を満たした      ║
> ╚══════════════════════════════════╝
> ```
> 「物語が分かった」ではなく **「ルールが増えた」** として提示する。
>
> **(b) 同じ Run 内でも使えるようにする。** K007 は取得したその Run の Boss 戦で
> すでに `[偽物だと告げる]` として使える。Knowledge は「次の Run のため」だけではない。
>
> **(c) 合成をその場で発火させる。** K007 取得時に K014 を持っていたら、
> **即座に** K022 が生成され「2 つの知識が結びついた」演出が入る。
> プレイヤーが何もしていないのに報酬が 2 つになる — これは強い。

### 修正後の判定: **合格。** ただし実装時に (a) の UI を手抜きすると全部台無しになる。
**実装優先度: 最高。** M7 の中でも最初に作る。

## Q5. 死亡後すぐ REWRITE を押したくなるか？

### 初稿の判定: **微妙。**

**問題 1 — RUN REPORT が「失ったもの」の話になっていた**

「Lv5 / Gold 240 / Skill 6 を失いました」は押す気を削ぐ。

> **修正**: RUN REPORT は **今回の収穫だけ** を表示する。失ったものは一切書かない。
> ```
>   このRUNで世界について分かったこと
>     ▸ K007  王女は偽物である          [NEW]
>     ▸ K014  司祭は入れ替わりを知っている [NEW]
>     ▸ K022  司祭が入れ替わりを手配した  [合成]
>   初めて見た場所   城・隠し部屋 / 教会・地下
>   最大シナジー     予見殺 (Premonition + Assassin)
>   書き換えた歴史   なし
>
>   次のRUNで新しくできること
>     ▸ REWRITE「王女を本名で呼ぶ」が解禁されました
>     ▸ ボス戦の選択肢が 2 つ増えます
> ```
> 最後のブロック **「次の RUN で新しくできること」** が REWRITE ボタンの動機になる。
> これが無い RUN REPORT は失敗作。

**問題 2 — REWRITE ボタンが「リトライ」と同義に見えた**

「もう一回」ではなく「**世界に手を入れる**」でなければタイトルの意味がない。

> **修正**: ボタンのラベルを状況で変える。
> - REWRITE 可能な行動がある: `▶ REWRITE — 王女を本名で呼ぶ` （具体的に何ができるかを書く）
> - まだ無い: `▶ REWRITE — 時間を巻き戻す`
>
> **押す前から「次に何をするか」が決まっている状態**にする。これが「もう一回」の正体。

**問題 3 — 死亡が「失敗」に見える**

> **修正**: 死因に応じて画面の文言を変える。
> - 灰の扉で死んだ → 「**あなたは知るために死んだ。それは無駄ではない。**」
> - Boss に負けた → 「**あなたはヴェインの第二形態を見た。次はそれを知っている。**」（K009 を渡す）
>
> **Boss 敗北時に必ず 1 つ Knowledge を渡す** ルールを追加した。負けても情報は手に入る。
> これにより「Boss に挑む」こと自体がリスクではなく投資になる。

### 修正後の判定: **合格。**

## その他、レビューで見つかった問題

### P1. 【重大】「知識を集めるほど簡単になる」問題

要求 §11 が警告している通り。初稿は Knowledge が単調増加するだけで、Run 10 の頃には
全ルートが既知になり難易度が崩壊していた。

> **修正 — 3 重の対策:**
> 1. **Invalidated**: REWRITE は必ず Knowledge を焼く。強い REWRITE ほど多く焼く（RW03 は K007 を焼く）
> 2. **Distortion**: 累積で敵が強化され、`schedule` タグの Knowledge が一斉に Uncertain 化する
> 3. **K017 / Loop Awareness**: Run 10+ のヴェインは K004（火）に耐性を持つ。
>    **プレイヤーのメタ知識が通用しなくなる**
>
> 特に 3 が要求 §16 の「プレイヤーだけがメタ知識を持つ優位性が崩れる」に直接応答している。

### P2. 【中】Skill 20 個のうち、戦闘で弱いものがある

`S09 Chronicler` `S20 Archivist's Loop` は戦闘性能ゼロ。
3 択に出たとき「ハズレ」に見えるとビルドの楽しさが損なわれる。

> **修正**: これらは **戦闘報酬の 3 択には出さない**。
> Discovery / Shrine ノード専用の報酬プールに分離した。
> 「戦闘の報酬で戦闘に使えないものを引かされる」事態を構造的に防ぐ。

### P3. 【中】シナジーが偶然に依存しすぎる

Y02（Premonition + Assassin）を狙っても、3 択に両方出なければ成立しない。
運任せのシナジーは「考える楽しさ」にならない。

> **修正**: Shop に **「求めるスキルの噂」**（Gold 60）を置く。購入すると
> 次の Skill 3 択に、**現在のビルドとシナジーを組むスキルが 1 枠確定で混ざる**。
> プレイヤーが能動的にシナジーを狙えるようになる。
> さらに UI で「所持スキルとシナジーするスキル」に ⚡ バッジを出し、**組み合わせに気付けるようにする**。
> （気付かれないシナジーは存在しないのと同じ）

### P4. 【中】1 Run 20-30 分に収まらない恐れ

ノード 7 + Boss で、各ノードが戦闘だと 8 戦闘。1 戦闘 3 分なら 24 分 + 移動判断。超える。

> **修正**: 戦闘ノードの比率を **50% 以下** に固定（Combat 3, Social/Discovery 2, Shop/Shrine/Rest 2）。
> 通常戦闘は **3〜4 ターンで終わる HP 設計**（雑魚 HP 24-40、プレイヤー攻撃力 10-18）。
> Elite と Boss だけが長期戦。実測で 20-25 分に収める。

### P5. 【小】Knowledge 合成が自動発火だと、プレイヤーの手柄にならない

> **判断: 自動のままとする。** 手動合成は「組み合わせ総当たり作業」になりテンポを壊す（§20 違反）。
> ただし **発火演出を強く**し、「あなたの集めた情報が繋がった」という主語にする。
> 加えて Knowledge 一覧画面に「あと 1 つで繋がりそうな組み合わせ」をヒント表示し、
> **プレイヤーが狙って取りに行ける**ようにする（手柄はここで返す）。

### P6. 【小】自由入力が「効かない」と 2 度と使われない

1 回失敗して「そんなことはできない」と返されたら、プレイヤーは二度と入力欄を開かない。

> **修正**: 自由入力は **必ず何かを返す** 設計にする。
> 1. 完全成功（engine が既知の行動に解決できた）
> 2. 部分成功（意図は通るがコストが高い / 別の結果になる）
> 3. **失敗だが情報が得られる**（「犬は皿に近づかない。何かがおかしい」→ K013 のヒント）
>
> 「何も起きない」は返さない。最低でも観察情報を返す。

### P7. 【小】MVP のコンテンツ量が要求を一部超過

要求は Knowledge 20 だが設計は 25（基礎 20 + 合成 5）。
Skill シナジーは 10 の要求に対し 11。

> **判断: 超過を許容する。** 合成 Knowledge は「基礎 20 件から生まれるもの」であり、
> 合成システムを実演するには最低 5 件必要。シナジー 11 個目は Y11（Cold Reading 救済）で、
> S19 が単体で弱すぎる問題への対処。どちらも削ると仕組みが成立しない。

## 最終判定

| 問い | 判定 |
|---|---|
| アドベンチャーゲームになっていないか | ✅ 合格（修正後） |
| AI を消してもローグライクとして面白いか | ✅ 合格。M1-M7 が LLM 非依存であることで構造的に保証 |
| AI を入れて何が生まれるか | ✅ 明確（未列挙の逸脱 / 余波の接着 / 記憶する NPC） |
| Knowledge 取得は嬉しいか | ✅ 合格（ルールとして提示 + 同 Run 内で使える + 即時合成） |
| すぐ REWRITE を押したくなるか | ✅ 合格（収穫のみ表示 + 次にできることを明示 + 死亡に意味を与える） |

**実装に進んでよい。** ただし以下を実装時の遵守事項とする。

1. `KNOWLEDGE ACQUIRED` のルール提示 UI を手抜きしない（Q4 の生命線）
2. `RUN REPORT` に失ったものを書かない（Q5 の生命線）
3. LLM を M8 まで一切呼ばない（Q2 の生命線）
4. AI の出力 Schema に数値フィールドを作らない（要求 §13 の生命線）
5. `npm run sim` で 3 Run 検証を自動化し、リグレッションを検出できるようにする
